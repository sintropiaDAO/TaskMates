- Task subtypes (meeting/event/project/service) live in `tasks.task_subtype` with config in `src/lib/taskSubtypes.ts`; portfolio metrics aggregate via `usePortfolioStats` — single source for labels and future portfolio filters.
- Save task subtype and contextual fields in the same insert/update as base fields before firing `onSaved`, so refreshed lists and detail modals cannot observe partially saved tasks.
- Public portfolios (`portfolios` table, `/p/$slug`) are assembled server-side in `src/lib/portfolio.server.ts` with the admin client, returning only public-safe fields and skipping hidden-community items — so viewers need no login and SSR can emit Open Graph tags.
- Dashboard-owned search and compact adventurer status render into AppHeader's dedicated slot via a portal, preserving dashboard selection callbacks while keeping both controls within the shared sticky header.
- Enforce parent visibility and profile blocking in database read policies through narrow fixed-search-path `can_view_entity`, `can_view_tag`, and `can_view_profile` definer predicates to avoid recursive RLS; task children cannot disclose inaccessible parents or hidden community links.
- Keep raw profile visibility settings owner-only; other profiles consume only effective display flags from `get_public_profile_visibility`, failing closed when access or loading fails.
- Preserve invite identity in a database trigger; recipients may change status and timestamps, never community or recipient, to prevent retargeting access grants.
- Public portfolio privacy checks include testimonials and community metadata and fail closed on lookup errors, because privileged assembly bypasses database read policies.
- Background push goes through Firebase Cloud Messaging: devices register tokens in `push_tokens` via server functions, and `createNotification` fans out with `sendPushToUser`; the FCM worker uses its own scope so it never collides with the kill-switch `/sw.js`.
- Journey (Jornada) progress is evaluated only in the database by `evaluate_journey_progress` (security definer, caller-scoped, counts actions after `joined_at`, one item per step); clients never write progress or completion, and completions go to `coin_ledger` (`JOURNEYS`) for idempotency. Step/indicator config and the EXP multiplier live in `src/lib/journeys.ts`.
- Journey public previews use the narrow `get_public_journey_preview` RPC through a server publishable client; private and archived journeys return no metadata to anonymous viewers.
- Journey covers reuse owner-folder uploads in `task-images`, normalized client-side to share-sized JPEGs; render the same saved cover without cropping in cards and details.
- Journey EXP counts durable ledger completions rather than deletable participant rows; serialize evaluation with participant locks and refresh journey/adventurer views through the shared progress event.
- Journey scores are personal ledger balances; refresh them on progress events and re-evaluate active journeys after dashboard activity lists change so creation counts without reopening the page.
